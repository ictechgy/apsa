# 공개 앱·CVE 보강 결과

[영문 문서](HARDENING_RESULTS.md)가 원본이다. [최초 결과](REAL_WORLD_RESULTS.ko.md) ·
[재평가 JSON](results/2026-10-09-public-real-world-hardened.json) ·
[실행·리뷰 근거](results/2026-10-09-hardening-evidence.json).

이후 파서·함수 커버리지와 Apple 분기 보강은 [커버리지 확장 결과](COVERAGE_RESULTS.ko.md)에
별도로 기록했다. 아래 과거 측정값은 dev2 스냅샷에 그대로 연결된다.

우선순위 네 가지 연동 문제를 수정하고 동일한 고정 공개 소스와 선택한 CVE
사례로 검증했다. 앱 6개 모두 검사가 완료됐지만, 6개 모두 감사 범위는 여전히
불완전하다. **정답을 확인한 뒤 수행한 개발 재평가**이며 작은 선별 정답 집합을
사용했다. 일반 탐지율, 앱 전체의 안전성, 악용 가능성이나 제품 우위를 입증하지
않는다.

평가한 규칙은 미배포 후보 `2026.10.09.apsa.111-dev2`다. 패키지 메타데이터는
`1.1.0`이지만 PyPI 1.1.0 평가 결과가 아니다. 변경은
`hardening/real-app-cve-v1` 브랜치에 올렸다.

독립 사례 32개는 TP 8·FP 0·FN 0·TN 19, 미확정 유보 5개다. 정밀도·재현율
100%는 **선택한 버전 확정 사례 27개 안에서의 수치**다. 관련 버전·라이브러리·
URL 표기 사례를 포함하며 서로 독립적인 앱 32개를 뜻하지 않는다. 이 사례들은
기존 OSV 응답을 그대로 재사용했고, 누락됐던 SwiftNIO HTTPS 식별자도 매칭했다.

실제 앱의 선택한 경로 4개는 TP 1·TN 3이다. AntennaPod의 jsoup 1.15.1을
Gradle 선언에서 추출해 조회·상관 분석까지 연결하고 CVE-2022-36033을 매칭했다.
상태는 `candidate`, 도달 가능성은 `unknown`이다. `$jsoupVersion`과 루트
`build.gradle:29` 근거를 유지하며 신뢰 수준은 `declared`다. 과거 컴파일된
앱의 설치 버전이나 악용 가능한 앱 결함을 확인한 것은 아니다. 함께 반환된
다른 CVE ID는 보존하되 이 정답 집합에서 점수화하지 않았다.

앱마다 같은 소스 ZIP을 세 번 검사해 관찰 결과가 안정적이었고, 독립 패키지·CVE
사례도 세 번 반복했다. 실제 앱 CVE 경로는 안정적인 소스 검사 인벤토리에서
별도의 선택 조회를 수행했다. 전체 소스 검사는 오프라인이다. 앱 코드·
Gradle/Xcode 빌드 스크립트·백엔드·기기를 실행하지 않았다. MobSF는 다시 실행하지
않았으므로 최초 비교에서 보강 후 제품·속도 순위를 도출할 수 없다.

## 수정과 한계

1. Android 패치 비교 전 기기·공지 양쪽 날짜가 실제 달력 날짜인지 검증한다.
   잘못된 날짜는 패치 충족을 뜻하지 않고 판단을 유보한다. iOS 사례 4개는 여전히
   미확인·기기 정보 필요·시뮬레이터 상태의 올바른 유지이며 양성 매칭 검증이 아니다.
2. 검사한 파일과 리터럴 로컬 import 사이에서 Gradle `ext` 상수를 해석하고,
   settings 파일의 프로젝트 경계에서 멈춘다. 충돌·동적 표현식·잘못된 구문·
   입력 누락·예산 초과는 미확정으로 유지한다. Gradle을 실행하거나 빌드 결과를
   해석하지 않는다. AntennaPod의 jsoup·OkHttp 소스 선언을 복구했다.
3. 지원하는 Swift 저장소 URL을 OSV 요청 경계에서만 정규화한다. 인벤토리·
   query-match·캐시 상관 분석은 원래 식별자를 유지한다. 선택한 SwiftNIO HTTPS
   CVE 매칭을 복구했다.
4. Xcode의 리터럴 INFOPLIST_FILE 참조로 이름이 다른 소스 plist를 발견하고,
   소스 디렉터리에서는 명시적으로 선택할 수 있다. Nextcloud의
   `Brand/iOSClient.plist`와 선택한 ATS 선언을 복구했다. 지원하지 않는 참조와
   여러 소스 설정은 불완전하게 처리하고 IPA/app의 주 식별자 선택은 엄격하게 유지한다.

6개 앱 모두 감사가 불완전하다. 특히 Firefox의 큰
`Client.xcodeproj/project.pbxproj`는 참조 검사 예산 200,000토큰을 초과했고,
참조된 Deferred plist 하나는 없거나 유효하지 않았다. 커버리지 경고로 명시했다.
기존 `Client/Info.plist`의 선택한 사실을 복구한 것이 설정 전체 검사 완료를
뜻하지 않는다. Swift·Kotlin 구문 복구 누락은 Firefox 78개·K-9 6개·Ice Cubes
2개 경로 등에 남았다. Objective-C 및 미지원 언어, 빌드 변형 병합, Apple CNA
별칭·custom 분기, 바이너리·기기·AAB·IPA 분석과 OS sandbox 동작은 이번 수정으로
입증한 커버리지 밖이다.

## 고정 재평가 근거

[성공한 재평가](https://github.com/ictechgy/apsa/actions/runs/37886018674)의 작업은
`113676092154`, 공개 실행 커밋은 `92cfcfddd7bd30ec20433da74baad58eb42bbb15`다.
로컬 리뷰 head `8ecc3f90dfbd5afe8e081a8707821b8c267fe4e7`와 공통 tree
`464344032f1dc6da44242dd799a2f6cc7ee9d997`로 동등함을 확인했다.

최초 입력 ZIP 6개·입력 manifest·제조사/CNA 정답·최초 결과·OSV 응답 29개를
보존하고 재평가 전에 해시를 검증했다. [최초 결과](results/2026-10-09-public-real-world-initial.json)의
SHA-256은 그대로다:
`a08769d89866515d3af1e772260cb944b970746f2599e77415a39c77747b2d32`.

**별도의 OSV 보충 응답 하나**가 필요했다. Maven `org.jsoup:jsoup` 1.15.1은
최초 실행에서 추출을 유보해 조회하지 않았다. 최초 공개 HTTP 200 응답을
`2026-10-09T04:46:41.465519+00:00`에
[실패한 재평가 37885440079](https://github.com/ictechgy/apsa/actions/runs/37885440079)에서
수집했다. 이 실행은 helper 응답 오류로 앱 검사·채점 전에 실패했지만 보충
응답은 artifact `11596401157`에 남았다. 성공한 재평가는 이 바이트를 가져와
payload·key·status·hash·size를 검증하고 OSV를 새로 수집하지 않았다. 기존 29개를
대체하지 않고 하나를 추가했다. 따라서 AntennaPod 실제 앱 경로 개선에는
별도 시점의 피드 응답이 포함되며 동일 피드 비교로 볼 수 없다. 독립 사례
32개는 처음부터 끝까지 기존 응답을 사용했다.

보충 manifest SHA-256:
`604ef9085abaca3dc460bd20bdcf3fb075b08efbd66256d86101fab6d0d3c5fe`.
응답 본문 SHA·요청 key·기존/합친 manifest 해시·artifact digest는 실행 근거와
재평가 JSON에 기록했다.

성공 artifact `11596049073`은 공개 입력·최초 결과/manifest·기존 및 보충 OSV
응답·재평가 보고서·summary를 포함한다. digest는
`sha256:0589d7fb1bfc4f297389cc8b5f11c7443e557721f6e527d5e827f3aad55fe903`이며
`2026-11-08T04:55:46Z`에 만료된다. 전체 오프라인 재실행에는 만료 전 두 입력
artifact를 보관해야 한다. 저장소의 요약과 고정 정답은 이후에도 남는다.
커밋한 재평가 JSON은 공개 작업 로그에 출력한 원본 JSON을 harness와 같은
정렬·들여쓰기 형식으로 복원했으며 파일 해시는 artifact digest와 별도로 기록했다.

## 검증과 다음 근거

[CI 37886018706](https://github.com/ictechgy/apsa/actions/runs/37886018706)의
Linux/macOS × Python 3.11/3.12 네 조합이 모두 통과했다. 테스트 784개, 포맷·
타입·독립 회귀 사례, 반복 빌드·저작권 고지, 깨끗한 오프라인 설치·CLI·MCP·
패키지 스킬 검사를 포함한다. 첫 CI에서 발견한 패키지 스킬 문서 불일치를
동기화한 뒤 통과했다. [코드·규격 리뷰](reviews/2026-10-09-hardening-code.md)는
`APPROVE`, [설계 리뷰](reviews/2026-10-09-hardening-architecture.md)는 `CLEAR`다.
두 리뷰 모두 위 실행 head/tree의 구현 변경 전체를 검사했다. 독립된 Codex
리뷰 두 경로에서 각각 판정했다.

일반 정확도를 주장하려면 이번 수정에 사용하지 않은 앱·CVE와 독립 정답으로
새 평가가 필요하다. 최신 Swift·Kotlin 파싱, 검사·누락 함수 커버리지, 제조사
근거에 따른 Apple CNA 분기 지원을 먼저 보강하고 바이너리·기기 검증을 넓혀야
한다. 이번 재평가에서 공개되지 않은 제로데이와 피드 완전성은 평가하지 않았다.
