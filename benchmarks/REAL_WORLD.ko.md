# 공개 앱 소스 및 CVE 평가 방법

[영문 문서](REAL_WORLD.md)가 원본이다. 이 평가는 개발용 합성 코퍼스와
분리한다. 최초 결과를 수집할 때까지 제품 분석 코드를 변경하지 않는다.
앱 커밋, 선택한 소스·설정 사실, 패키지 버전, CVE의 예상 상태는
real_world_cases.json에 고정한다.

대상은 실제 공개 앱의 소스 스냅샷 6개다. Android는 NewPipe·AntennaPod·K-9
Mail, iOS는 Firefox·Nextcloud·Ice Cubes다. 과거 릴리스와 개발 소스를 변경
불가능한 커밋으로 식별하며, 최신 출시 버전이라고 표현하지 않는다. 이
평가로 현재 배포 중인 앱의 보안 상태를 판단할 수 없다.

일회성 GitHub 실행 환경에서 공개 소스와 제조사 공지만 내려받는다. 앱 코드나
빌드 스크립트를 실행하지 않고 앱 서버에 접속하거나 앱을 설치하거나 사용자
데이터를 읽지 않는다. 고정된 저장소 압축 파일에서 텍스트·설정 파일만 원래
바이트 그대로 다시 묶고 미디어를 제외한다. 주요 파일의 Git blob 해시를
검증한 뒤 동일한 ZIP을 실제 APSA CLI와 고정된 MobSF 서비스에 전달한다.

## 구분해서 측정하는 항목

1. 전체 소스 실행: 완료 여부, 반복 결과의 일관성, 검사한 파일·바이트,
   규칙별 커버리지와 불완전성, 도구별 경고 수, 작업 실행 시간이다. APSA의
   finding과 MobSF의 규칙 항목은 단위가 달라 개수로 우열을 정하지 않는다.
   세 번의 반복은 통계적 유의성을 입증하지 않는다. APSA는 매번 새
   프로세스로 실행하고 MobSF는 CPU 2개·메모리 4 GiB의 서비스를 재사용하므로
   시간은 분석 엔진 자체의 속도 비교가 아니다.
2. 선택한 설정 사실 6개: 지정한 주요 파일의 명시적 cleartext·ATS 선언이다.
   악용 가능한 취약점 6개를 뜻하지 않는다. 브라우저·팟캐스트·개인 서버
   클라이언트는 넓은 전송 예외를 의도적으로 허용할 수 있다. 선택한 설정을
   검사하지 못하면 정답 음성으로 인정하지 않는다. 소스 선언은 최종 릴리스에
   병합된 manifest를 입증하지 않는다.
3. 선택한 의존성 사실 10개: 리터럴, 버전 카탈로그, resolved pin, 외부 Gradle
   변수에서 확인한 이름과 버전이다. 컴파일된 의존성 그래프가 아닌 소스의
   선언을 정답으로 삼는다. 소스 버전만으로 실제 포함 여부나 취약한 기능의
   실행 가능성을 판단할 수 없다.
4. 독립 패키지·CVE 사례 32개: 해당 CVE의 영향 버전 8개, 비영향 버전·다른
   패키지 19개, 의도적으로 버전을 확정하지 못한 입력 5개다. 정답은 OSV
   응답이 아닌 CNA·제조사 릴리스 근거에서 정한다. Okio의 두 수정 분기와
   SwiftNIO의 2026년 수정, 다른 패키지 그룹·생태계·URL 표현·수정 경계를
   포함한다. 다른 CVE가 반환되면 매칭 ID에 남기지만 선택한 CVE의 오탐으로
   계산하지 않는다.
5. 실제 앱의 선택한 CVE 경로 4개: 실제 추출한 의존성으로 OSV 조회와 APSA
   상관 분석을 수행한다. AntennaPod의 jsoup 1.15.1 선언은 CVE-2022-36033의
   영향 버전이다. 선택한 NewPipe·K-9의 jsoup 버전과 K-9의 Okio 버전은 해당
   CVE의 영향 범위 밖이다. 영향 버전을 추출·조회하지 못하면 전체 경로
   재현율의 누락으로 계산하며 정답 음성으로 바꾸지 않는다.
6. OS 상관 분석 사례 11개: 실제 Apple·Android 공지와 새로 만든 환경 정보를
   사용한다. 패치 경계, 기기 정보 부족, 시뮬레이터, 공지에 없는 릴리스,
   잘못된 패치 날짜, 지원하지 않는 CNA custom 범위를 확인한다. 판단 유보와
   매칭 커버리지를 구분한다. 실제 기기 관찰이나 공격 재현 결과는 아니다.

## 공개 취약점 정보 고정

실제 제품의 query_dependencies와 correlate 함수를 호출한다. OSV HTTP
응답을 요청 내용·상태·해시와 함께 한 번 수집하고 이후 반복에서는 같은
바이트를 재생한다. 이는 조회 연동, 정규화, 패키지 식별, 보고서 상관 분석을
검증한다. 패키지·버전 범위 매칭은 OSV에 위임하므로 독립 APSA 범위 데이터베이스를
OSV와 비교하거나 피드의 완전성을 입증하는 평가가 아니다. CNA·GitHub 기록은
저장소에 고정하고 제조사 HTML 및 조회 응답은 실행 아티팩트에 보존한다.

실패·버전 미확인·반복 불일치는 정답 음성으로 집계하지 않는다. 완료된 사례의
재현율과 영향 버전의 실패까지 포함한 전체 경로 재현율을 함께 표시한다.
버전 미확인은 별도의 판단 유보 지표로 기록한다. 모든 취약점의 독립 정답
집합이 없으므로 앱 전체의 취약점 정밀도·재현율은 정의하지 않는다. 편의
표집과 선택한 사실만으로 일반적인 실제 앱 정확도나 시장 순위를 주장할 수
없다. 상용 도구, 바이너리 빌드, 기기, AAB·IPA, 실행 가능성, 공개되지 않은
제로데이 탐지는 평가하지 않는다.

최초 공개 원본 보고서와 입력 해시를 보존한다. 이후 누락을 고치면 이미
관찰한 입력으로 수행한 결과를 개발 재평가로 표시하고 최초 결과와 고정
정답을 함께 남긴다.
