# 공개 앱 소스 및 CVE 매칭 평가 결과

[영문 문서](REAL_WORLD_RESULTS.md)가 원본이다. [평가 방법](REAL_WORLD.ko.md) ·
[최초 결과 JSON](results/2026-10-09-public-real-world-initial.json) ·
[입력·조회 및 진단 근거](results/2026-10-09-public-evidence.json).

[이후 보강 재평가](HARDENING_RESULTS.ko.md)는 관찰한 입력에 대한 수정 결과다.
아래 최초 결과와 점수는 그대로 유지했다.

최초 평가에서 유효한 매칭과 구체적인 연동 누락을 확인했다. APSA는 공개 앱
소스 6개 중 5개를 분석 완료했지만, 완료한 5개 모두 감사 범위가 불완전했다.
독립 CVE 사례는 TP 7·FP 0·FN 1·TN 19였고, 버전 미확정 입력 5개는 올바르게
판단을 유보했다. 실제 앱에서 유일하게 영향 버전으로 지정한 경로는 Gradle
변수를 풀지 못해 조회를 유보했다. 잘못된 Android 패치 날짜를 패치 충족으로
판정한 오류도 확인했다.

이 결과는 수정 우선순위의 근거이며 일반적인 실제 앱 정확도나 제품 순위를
의미하지 않는다. 최초 평가 중 제품 분석 코드를 변경하지 않았다. 평가한
규칙은 미배포 벤치마크 후보 `2026.10.09.apsa.111-dev`다. 패키지 메타데이터는
`1.1.0`이지만, PyPI에 배포된 1.1.0 구현의 평가 결과가 아니다.

## 실행 및 근거

[최초 실행](https://github.com/ictechgy/apsa/actions/runs/37879443007)과 작업
`113655489966`은 성공했다. 실행 성공은 평가 절차가 끝났다는 뜻이며 개별
분석기의 실패는 결과에 남긴다. 공개 실행 커밋은
`5513aa0d4466f8ce0413c4720a3f2e470e417924`, 로컬 리뷰 커밋은
`8c5a90787bcafd9484071611ad496f0453a2ff1e`, 공통 트리는
`42c8b6c9cb3beef83f630c951ac5d5e23f285db4`다.

앱마다 동일한 소스 ZIP을 두 도구에 세 번씩 전달했다. 원본 텍스트·설정 파일
바이트를 유지하고 미디어를 제외했다. 앱 코드·빌드 스크립트·서버·기기를
실행하지 않았다. 저장소 전체에 테스트·라이브러리·빌드 변형이 포함되므로

반복에서 달라지지 않았다. 경고 집계 단위가 다르고 모든 취약점의 독립 정답이
없어 어느 도구가 실제 취약점을 더 많이 찾았다고 결론 낼 수 없다. MobSF의
K-9 HTTP 실패는 이 소스 묶음에서 관찰한 연동 실패이며 원인은 확정하지
않았다. MobSF는 APSA와 동일한 규칙별 커버리지 지표를 제공하지 않는다.
MobSF의 CVE 정확도나 상용 도구와의 비교는 평가하지 않았다.

APSA는 여러 소스 설정을 관찰했으며 빌드 시스템 병합을 수행하지 않았다고
명시했다. Kotlin·Swift 구문 복구 과정에서 해당 함수 검사를 건너뛰었고,
관련 경고는 Firefox 78개 경로·K-9 6개 경로·Ice Cubes 2개 경로에서 발생했다.
지원하지 않는 소스 언어와 오프라인 취약점 정보도 커버리지를 제한했다.
따라서 Ice Cubes의 finding 0개는 앱이 안전하다는 뜻이 아니다. 전체 소스 CLI
검사는 오프라인이었으며 선택한 의존성·CVE 연동은 별도로 실제 OSV 조회를
수행했다.

시간은 이 실행 환경의 비용이다. APSA는 새 프로세스, MobSF는 CPU 2개·메모리
4 GiB의 서비스 재사용 방식이므로 세 번의 반복 시간으로 엔진 속도 순위를
정할 수 없다.

## 선택한 소스 사실

명시적인 cleartext·ATS 설정 사실 6개 중 5개를 검사하고 올바르게 분류했다.
Nextcloud의 `Brand/iOSClient.plist`는 APSA 분석이 실패해 검사하지 못했다.
[고정 입력 진단](https://github.com/ictechgy/apsa/actions/runs/37880872218)에서도
종료 코드 1과 `Archive has no readable Android manifest or main iOS Info.plist`가
재현됐다. 고정된 Xcode 프로젝트는 INFOPLIST_FILE로 Brand/iOSClient.plist를
선택한다. APSA 입력 리더는 Info.plist로 끝나는 이름을 인식해 이 유효한
소스 설정을 지원하지 못했다.
악용 가능한 취약점 6개나 컴파일된 앱의 전송 정책을 평가한 것은 아니다.
AntennaPod·K-9에는 network security configuration도 있으므로 넓은 cleartext
선언은 맥락과 함께 검토해야 한다.

선택한 의존성 이름·버전 선언은 10개 중 8개를 올바르게 추출했다. 누락된
두 개는 AntennaPod의 외부 Gradle 변수인 jsoup 1.15.1과 OkHttp 4.12.0이다.
제품은 값을 추측하지 않고 `$jsoupVersion`·`$okhttpVersion`을 미확정 상태로
유지했다. Nextcloud에는 선택한 정확한 버전 정답이 없다. Xcode의 최소 요구
버전을 설치된 버전으로 간주하지 않았다.

## 독립 패키지·CVE 사례

정답은 실행 전에 제조사·CNA 근거로 고정했으며 평가 대상인 OSV 응답으로
정하지 않았다. 실제 제품 함수 query_dependencies·correlate를 호출했고,
패키지·버전 범위 조회는 OSV가 수행했다. 동일한 요청은 최초 응답 바이트를
수집한 뒤 반복 검사에서 재생했다.
보존한 OSV manifest에는 독립·실제 앱 검사에서 수집한 고유 HTTP 응답
스냅샷 29개가 있으며 모두 상태 코드 200이다.

버전이 확정된 27개 사례는 피드 실패나 반복 불일치 없이 완료했다.

미확정 5개는 별도의 판단 유보이며 TN에 넣지 않는다. 작은 선별 집합이므로

누락은 SwiftNIO 2.99.0의 `https://github.com/apple/swift-nio` 입력이다. 같은
버전을 `github.com/apple/swift-nio`로 조회하면 CVE-2026-28970이 매칭됐지만,
HTTPS 표현은 매칭이 없었다. 실제 Package.resolved 추출이 HTTPS 주소를
유지하므로 실제 iOS 입력과 연결되는 연동 누락이다. 영향·수정 경계는
[제조사 공지](https://github.com/apple/swift-nio/security/advisories/GHSA-cq87-8r7h-962v)에서
독립적으로 고정했다.

비영향은 **지정한 CVE**의 범위 밖이라는 뜻이다. 일부 jsoup·Bouncy Castle
대조군에서 다른 CVE ID가 반환됐으며 JSON에 유지했다. 해당 추가 기록은
독립 정답을 부여하지 않았으므로 확인된 앱 결함이나 이번 선택 CVE의
오탐으로 분류하지 않는다. 의존성 매칭으로 실행 가능성이나 악용을 입증할
수 없다.

## OS 공지 상관 분석

예상 상태 11개 중 10개가 기준대로 동작했다. 실제 공개 공지와 합성 기기
정보를 사용했으며 실제 기기 검사나 공격 재현이 아니다. iOS 사례 4개는
기기 정보 필요·시뮬레이터·알 수 없음 상태를 유지한 것으로, 영향 iOS 버전의
양성 매칭을 입증하지 않는다. Apple CNA 제품명과 custom 버전 분기는
커버리지의 한계로 남아 있다.

Android의 `2024-99-99`를 `vendor-patch-level-satisfied`로 잘못 판정했다.
상관 분석기가 날짜 모양만 확인하고 실제 달력 날짜인지 검증하지 않은 채
문자열을 비교한다. 정보 부족이나 적용 여부 미확인으로 처리해야 한다.
합성 입력이라도 잘못된 보안 확신을 주는 결함이다. 유효한 2024-09-01 경계는
[Android 2024년 9월 공지](https://source.android.com/docs/security/bulletin/2024-09-01)에
대해 통과했다. [Apple iOS 18.3.2 공지](https://support.apple.com/en-us/122281)와
고정된 CVE-2025-24201 CNA 기록도 보존했다.

## 수정 우선순위

1. Android 패치 날짜를 실제 달력 날짜로 검증하고 잘못된 입력에서 패치 충족
   상태가 나오지 않게 한다.
2. Gradle을 실행하지 않고 지원 가능한 리터럴 변수만 파일 간에 해석한다.
   동적 값은 미확정으로 유지하고 정적 추출이 어려우면 resolved SBOM을 받는다.
3. OSV 조회 경계에서 지원하는 Swift 패키지 식별자를 정규화하고 원본 저장소
   URL을 근거로 유지한다.
4. Xcode INFOPLIST_FILE이 가리키는 이름이 다른 plist와 명시적 설정 선택을
   지원한다. 앱·빌드 변형의 모호함을 임의로 해소하지 않는다.
5. 최신 Swift·Kotlin 파싱과 검사·누락 함수 커버리지를 개선한다. 제조사 근거를
   통해 지원하는 Apple CNA 제품명·버전 분기를 확장한다.

최초 평가에는 위 수정이 포함되지 않는다. 수정 후 같은 입력을 사용하면 개발
재평가로 표시하고 최초 점수를 남겨야 한다. 일반 정확도를 주장하려면 새 독립
평가 집합이 필요하다. 바이너리·기기·AAB·IPA, Objective-C 분석 깊이, OS sandbox,
피드의 완전성, 공개되지 않은 제로데이는 평가하지 않았다.

## 보존한 근거

최초 결과 값은 변경 없이 저장소에 기록했다. 정규 JSON SHA-256은

아티팩트 `11593238939`에는 공개 소스 ZIP, 제조사 HTML, OSV 요청·응답 스냅샷,
원본 보고서가 있으며 digest는
`sha256:30fb74fd21788fd0d2a50ee80723d164f335121fe4d75189727ee321bc7e616e`다.
