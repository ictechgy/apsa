# APSA / MobSF 합성 비교 — 2026-10-09

[영문](COMPETITIVE_RESULTS.md)이 원본이며 이 문서는 그 내용을 따릅니다.

[완료한 교정 실행](https://github.com/ictechgy/apsa/actions/runs/37808597054)에서
실제 APSA CLI와 MobSF 서비스를 동일한 새 합성 입력으로 비교했습니다.
소스 ZIP 40개와 컴파일한 APK 6개를 각각 3회 검사했습니다. 위험 패턴과
수정·무관 사례의 정답 및 규칙 매핑은 APSA 수정 전에 고정했습니다.
교정 실행의 선택 검사 단위는 감지된 내부 분석 실패나 반복 결과 불일치 없이
완료했습니다. 이전 APK 실행은 숨겨진 디컴파일 실패를 발견해 제외했습니다.

확인한 성과는 APSA 소스 검사 개선입니다. 배포판에서 놓친 선택 위험 패턴
4개와 대조군 경고 4개를 수정 후보에서 해소했습니다. 이 사례를 보고 수정했으므로
개발용 사례의 성적이며, 운영 앱 정확도나 제품 전체 순위를 나타내지 않습니다.

## 소스 ZIP 결과

Java 23개, Kotlin 6개, Swift 11개입니다. 선택한 위험 패턴은 18개,
그 위험이 없도록 수정하거나 무관하게 만든 대조군은 22개입니다.
사례별 선택 범주만 채점하며 다른 발견 항목은 원본 보고서에 보존합니다.

| 도구 | 위험 탐지 / 18 | 누락 | 대조군 경고 / 22 | 선택 경고의 정밀도 |
| --- | ---: | ---: | ---: | ---: |
| 배포 APSA 1.1.0 | 14 | 4 | 4 | 77.8% |
| 미배포 APSA `111-dev` | 18 | 0 | 0 | 100% |
| 이미지 고정 MobSF 4.5.3 | 12 | 6 | 4 | 75.0% |

MobSF 누락 6개 중 4개는 고정한 규칙 목록에 직접 대응 규칙이 없는 URL 사례입니다.
두 도구에 모두 대응 규칙이 있는 범주만 보면 위험 패턴 14개, 대조군 18개입니다.
이 부분집합은 기존 매핑에서 도출하며 관측 결과로 규칙이나 정답을 바꾸지 않았습니다.

| 도구 | 공통 대응 범주 위험 탐지 / 14 | 대조군 경고 / 18 |
| --- | ---: | ---: |
| 배포 APSA | 10 | 4 |
| APSA 후보 | 14 | 0 |
| MobSF | 12 | 4 |

나머지 MobSF 누락은 이 Kotlin 소스의 SSL·로그 사례입니다. 해당 ZIP 구성과
소스 형태에 대한 관측이며 Kotlin 앱 전반의 분석 능력을 뜻하지 않습니다.
MobSF 대조군 경고는 무관한 `proceed()` 호출, Java·Swift의 가린 로그,
파라미터 바인딩 SQL에 나타났습니다. 넓은 검토 경고도 유용할 수 있으나,
여기서는 더 좁게 정의한 위험에 대한 검토 부담으로 집계합니다.

Kotlin SSL 2개 사례에는 APSA AST 구문 복구에 따른 부분 검사 표시가 남아 있습니다.
선택 발견 항목과 검사 범위·경고를 보존합니다. 공개 취약점 정보와 런타임 검사는
측정하지 않았으며, 선택 범주에서 발견 항목이 없다고 앱 전체가 안전한 것은 아닙니다.

준비하고, 코드 분석 내부 실패를 검사 실패로 구분했습니다.
초기 [기준판](results/2026-10-09-initial-released-baseline.json)과
[후보·MobSF](results/2026-10-09-initial-candidate-mobsf.json) 요약은 별도로 보존합니다.
그 안의 초기 APK 숫자를 탐지 성적으로 재사용하면 안 됩니다.

## 수정과 검증

후보는 프레임워크 호출 근거가 있는 명시적 AES/ECB와 약한 해시 선택,
Swift 클로저 안의 CommonCrypto 호출, Android 플랫폼 입력에서 SQLite SQL 문장으로
이어지는 로컬 흐름을 검사합니다. 모두 범위가 명시된 후보 항목입니다.
약한 해시 API의 사용만으로 보안 목적이나 악용 가능성을 확정하지 않습니다.

AST 근거가 있는 리터럴 로그 가림과 로컬 비 SDK 핸들러 호출에만 패턴 제외를 적용합니다.
실제 값을 이어 붙이기, 문자열 보간, 예외 인자, 로그 태그에만 넣은 가림 표시,
같은 줄의 추가 민감 로그, 구문 복구에서는 넓은 검사를 유지합니다.
UTF-8 바이트 범위로 한글 주석이나 탐욕적 정규식이 실제 근거를 숨기지 않도록 했습니다.

별도 회귀 사례 25개가 이 경계를 검증합니다. 이는 독립적인 블라인드 벤치마크가 아닙니다.
제품 수정 후 전체 테스트 692개와 수정·소스 파일 lint 및 타입 검사가 통과했습니다.
최종 실행 코드의 벤치마크 검사 21개와 코드·구조 독립 리뷰가 통과했습니다.
[일반 hosted CI](https://github.com/ictechgy/apsa/actions/runs/37808596752)도 통과했습니다.
리뷰 승인은 해당 스냅샷에 적용되며 배포를 뜻하지 않습니다.

## 재현과 출처

[프로토콜](COMPETITIVE.md), [배포판 요약](results/2026-10-09-released-baseline.json),
[후보·MobSF 요약](results/2026-10-09-candidate-mobsf.json)을 제공합니다.
전체 입력·컴파일 근거·원본 보고서는 실행의 합성 artifact에 있습니다.
구체적인 실행, 이미지, 도구 및 입력 해시와 보존 기간은 영문 원본에 기록합니다.

실행한 후보·벤치마크 커밋은 `43cafbafae6ff74ab65e5a1382b97f193b015d52`이며,
소스 트리는 `b76b6ef26edee48b6144d2929b914ea401cd6316`입니다.
두 엔진에 사용한 입력 manifest의 SHA-256은
`a0117b72ed166dda11f95d085806bd9cd36dbe7a94739d01a9985e55fb8b1682`입니다.
MobSF 4.5.3의 소스 커밋은 `d3869adc464b89db92a6a8a9e2dc13376f4a4c25`이며,
실제 이미지 digest는 영문 원본과 실행 요약에 보존했습니다.
공개 [JADX 1.5.0](https://github.com/skylot/jadx/releases/tag/v1.5.0)의
ZIP SHA-256은 `c5a713fa4800cbb9e6df85ced1bef95ba329040c95cb87d54465f108483e4ef9`입니다.
버전·크기를 확인했으며 이 해시는 내려받은 바이트의 기록입니다.
상위 프로젝트의 기대 digest가 제공되지 않아 서명 검증을 뜻하지 않습니다.
[전체 합성 artifact](https://github.com/ictechgy/apsa/actions/runs/37808597054/artifacts/11564840911)는
2026-11-07까지 보존됩니다. 입력·컴파일 근거·원본 보고서를 포함하며
ZIP digest는 `sha256:0a98b1c690092d3f652adc863e086ce132c2bd4e9f180d5ae468046708565899`입니다.
요약 JSON은 이 저장소에 남습니다.

기준 엔진은 별도 환경에 설치한 고정 커밋 `6d2216e8ade07208c0b0495507b81574dbb64c61`입니다.
기준판과 후보의 기록된 엔진 파일 30개 해시를 각각 고정 소스와 대조했습니다.
요약의 `source_revision`은 기준판에서도 실행한 **벤치마크 코드의 커밋**입니다.
기준 엔진 식별은 기준 커밋과 `apsa_engine`을 사용합니다.
후보의 패키지 버전은 여전히 1.1.0이지만 개발 규칙 버전은
`2026.10.09.apsa.111-dev`이며 PyPI에 배포하지 않았습니다.

APSA는 새 CLI 프로세스와 저장소, MobSF는 준비된 서비스에 업로드·재검사하는 비용을
측정합니다. MobSF에는 CPU 2개·메모리 4 GiB를 지정했습니다. 설치·이미지 다운로드는
제외하며, 실행 시간으로 엔진 자체의 속도 순위를 주장하지 않습니다.
CPU·RSS 비용과 통계적 유의성은 측정하지 않았습니다.
사례별 중앙 실행 시간은 기준판·후보·MobSF 순서로 소스에서
0.226/0.224/0.998초, APK에서 0.380/0.370/2.861초였습니다.
이전 `37802283185`, `37804348298` 실행은 서비스 연결 단계에서 중단돼
경쟁 도구 성적으로 사용하지 않습니다. 완료 실행은 새 내부 Docker 네트워크의
확인한 서비스 IP를 사용하며 포트를 공개하지 않고 사용자 앱 입력을 사용하지 않았습니다.

## 경쟁력 방향과 다음 검증

이번 결과는 정확히 범위를 설명하는 로컬 소스 검사와 검토 흐름의 품질에 투자할
근거가 됩니다. MCP 제공 자체가 정확도나 독점적인 차별점을 증명하지는 않습니다.
넓은 검사 범위, 런타임 기능, 취약점 정보 품질, 모델 연결 성능이나 상용 제품은
비교하지 않았습니다.

다음 검증은 개발 사례와 분리한 실제 오픈소스 앱을 독립적으로 라벨링하고,
소스와 배포 빌드, 규칙 적용 여부, 분석 실패, 경고 검토 시간과 자원 비용을
함께 측정하는 것입니다. iOS 내장 바이너리, Objective-C, AAB·난독화와 실제 기기
테스트는 별도 그룹으로 추가하고, CVE·OSV 대조는 영향을 받는 버전·수정 버전 및
패치 상태 근거가 있는 고정 공지 스냅샷으로 검증해야 합니다.
