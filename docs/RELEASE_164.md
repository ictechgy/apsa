# APSA 1.6.4

Package version: `1.6.4`. Rule version: `2026.10.30.apsa.164`.

This release addresses regressions observed while statically analyzing public
Android apps and public Orca desktop source. App code was not executed and no
device or credential service was contacted.

- The bounded JS/TS/Dart binding parser checks both ends of token ranges, avoiding
  a crash on a postfix increment/decrement at the end of a function body.
- Private-key detection requires matching BEGIN/END labels and plausible bounded
  body content. Header/footer recognizer constants alone are not key material.
  Complete synthetic or public test material remains a masked candidate; this
  does not validate a key, establish deployment, or prove a credential leak.
  Concatenated source literals, Kotlin margin-prefixed strings and JSON-escaped
  slash bodies are not reconstructed into keys. Recognizable unsupported
  prefixes within a 512-character lookahead retain partial screening coverage
  instead of becoming findings. This is a bounded raw-text screen, not program
  evaluation: arbitrary comments, distant fragments and other encodings are
  outside its coverage. A `checked` state completes that named screen; it does
  not establish the absence of dynamically assembled keys.
  The screen is line-oriented: same-line header/body/footer envelopes are not
  recognized. Screening caps preserve uncertainty across supported opening,
  body, metadata, footer and recognized reconstruction prefixes.
  Repeated valid header lines are screened without repeated large text copies.
- Apple source inventory separates positive iOS/macOS evidence from ambiguous
  Swift. The presence of a Swift file alone does not establish an iOS app.
  Common Apple source security checks remain available without inventing an
  iOS app identity. Conditional and inherited hints retain uncertainty; SwiftPM
  deployment minimums do not prove exclusive target membership. Mixed platform
  scope remains partial. See [SwiftPM deployment settings](https://docs.swift.org/latest/documentation/packagedescription/supportedplatform/).
  Qualified Swift imports retain their framework hints. Import-looking text in
  Swift regex literals does not establish platform evidence. Simple string
  interpolation retains platform hints when its bounded parentheses resolve
  without nested literal syntax. Complex interpolation and unresolved lexical
  syntax retain partial scope rather than proving desktop-only membership.
  Ambiguous no-space division involving contextual or underscore-prefixed names
  can also retain partial scope; clear ASCII-spaced division remains supported.
  Non-ASCII whitespace is not treated as proof of a division operator.
  Privacy declarations in
  short module paths and shared resource directories remain available when a
  desktop ancestor import does not prove their exclusive target membership.
  Positive macOS-only source plist evidence does not establish an iOS app or
  complete mobile coverage; compiled-package identity requirements remain intact.
  C/NDK headers alone do not enable common Apple source rules.
  Desktop privacy-source exclusion requires direct, unconditional Swift framework
  evidence; Objective-C platform classification and inferred sibling membership
  are not resolved by that exclusion. Modules containing unclassified Objective-C
  sources retain their observed privacy declarations.
- Repeated hybrid input omissions produce counted diagnostics. Each observed
  file retains its skipped state and reason in `inventory.hybrid_analysis.files`;
  aggregated warnings do not mean that omitted code was checked.

Source directories and source ZIPs use the same identity policy: missing mobile
manifests do not prevent supported source screening and do not establish an app
identity. Compiled APK/IPA and app-bundle identity requirements are unchanged.

MCP's bounded report context does not include the complete per-file analysis
inventory. For every omission path and reason, export the local report with
`apsa reports export REPORT_ID --format json --out report.json` and inspect
`inventory.hybrid_analysis.files`. MCP warnings retain counted incompleteness;
they do not establish that each omitted path is accessible through report pages.

Rescan before comparing or approving a baseline: corrected platform scope and
removed header-only candidates can change observations. An absent finding does
not by itself prove remediation.

Existing iOS source repositories can newly report partial coverage, including
SwiftUI-only apps, XCTest targets and projects whose Info.plist is generated by
Xcode. These source hints do not establish build-target membership. The Action's
`fail-on-incomplete: "true"` setting can therefore fail such scans; inspect the
coverage reasons or analyze the built artifact before approving a baseline.

Analysis remains bounded and partial. Hermes bytecode is not decoded, source
file/byte/function limits are unchanged, and the hybrid engine is not a complete
JavaScript/TypeScript/Dart grammar. Static candidates do not establish runtime
reachability or exploitability. This release includes CLI, MCP and plugin
metadata updates; it does not include a GUI installer.

Publication is performed by the existing immutable-tag workflow after independent
review and hosted checks. PyPI/MCP/GitHub publication and Linux/macOS public
installation checks are separate gates; a local build alone is not publication.
